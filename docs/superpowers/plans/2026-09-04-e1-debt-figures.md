# E1 · §7 and §8 — the debt figures, on the phone — Implementation Plan (wave 4a)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Read `2026-09-04-wave-4-shared.md` first.

**Goal:** The phone answers *who owes what* and *what is unallocated* with no server: `counterparty_balances` per person per currency with FIFO ageing for companies, and `find_unsettled` naming the oldest unconsumed transaction, plus §8's largest-remainder allocation as a pure function — each a fold in `money.ts` with a differential test against the SQL where SQL exists.

**Architecture:** A1 already built `counterpartyBalance(rows)` (per-currency sums) and `unsettledClearing` (a filter that defers FIFO). This PR adds the three pieces they deferred: `fifoOldestOpen` (one algorithm serving both §7 ageing and §8 attribution), `ageBucket`, `allocateLargestRemainder`; readers in `packages/ledger/src/counterparties/read-counterparty-balances.ts` and `accounts/read-unsettled-clearing.ts` (extend) that resolve `side` and `coalesce(debt_currency, currency)` from rows and call the folds; server SQL for `find_unsettled` beside `counterparty-balance.ts` in `packages/db/src/figures/`, and the differential test extended to both. Port/snapshot: `counterpartyBalances`, `unsettledClearing` gains `oldestUnconsumedTransactionId` and `oldestDate`.

**Spec:** `computations.md` §7, §8, §0 (class), §0a (rounding) · `SPEC.md` §6.4, §6.6, §6.7 (contributions structurally excluded) · O15 (companies only) · `screens/S12` §5, §8 · `S13` §5.

**Board cards closed:** *§7 counterparty balances · class F* · *§8 clearing + largest-remainder allocation · class F/S* · the read half of *Reads — debt and FX (6 ops)*: `counterparty_balances`, `find_unsettled` (the FX reads are E3's).

**Branch:** `feature/e1-debt-figures` off `main`.

## Tasks

1. **`fifoOldestOpen`.** `money.ts`: `fifoOldestOpen(deltas: readonly { id; date; delta: Money }[]): { id; date } | null` — sort by `(date, id)`; the sign of the running total decides which deltas *open* (same sign as the final balance) and which *consume*; a queue of open rows with remainders, each consumer taking from the oldest; return the oldest open row with a positive remainder, or `null` when the balance is zero. Property test (`fast-check`): the returned row's remainder is positive; a zero balance returns `null`; consuming in any order of arrival for the same date is stable by `id`. Worked test from §7's table (lend 200 · repay 200 → null; lend 200 · lend 300 · repay 200 → the 300's row).
2. **Ageing.** `ageInDays(oldestDate, today)` over `AccountingDate` (bare-string day arithmetic through `date.ts`, never `Date`), `ageBucket(days): "0-30" | "31-60" | "61-90" | "90+"`. The label rule is the screen's (*old*, never *overdue* — no `payment_terms_days`), so the function only buckets.
3. **`allocateLargestRemainder`.** `allocateLargestRemainder(total: Money, weights: readonly number[], decimals: number): readonly Money[]` — floor each share at scale, distribute the remainder one minor unit at a time by descending fractional part, ties by index. Never `total × (1/n)`. Tests: `185.00` three ways → `61.67 / 61.67 / 61.66`, sums exactly; `100.00` three ways → `33.34 / 33.33 / 33.33` (J08 §5); weights `2·1·1`; a property test that `sum(shares) === total` for any total and weights.
4. **Counterparty balances reader.** `readCounterpartyBalances(db, today)`: one query over live `debt`-role rows joined to `counterparties` (kind, settlement currency, archived), resolving `side` (`'to'` for `transfer`, else `'from'` — §7's rule verbatim) and `coalesce(debt_currency, currency)` in application code, folded with `counterpartyBalance`; for `kind = 'company'` also `fifoOldestOpen` per currency → `ageDays`, `bucket`. Returns `LocalCounterpartyBalance = { counterpartyId; name; kind; settlementCurrency; currency; decimals; balance; ageDays: number | null; bucket }[]`. Direction totals (S12's *they owe you* / *you owe*) are per currency, never across people — return them as `{ currency; theyOwe; youOwe }[]` from a second small fold, `directionTotals`, in `money.ts`.
5. **`find_unsettled`.** Extend `readUnsettledClearing` so each row carries `oldestUnconsumedTransactionId`, `oldestDate` from `fifoOldestOpen` over the account's own legs (inflows open, outflows consume — write that reading into `computations.md` §8 in one sentence, as the shared plan says). Server twin `packages/db/src/figures/find-unsettled.ts` (SQL window over the same ordering) and `differential.test.ts` extended: the fixture gains two counterparties (one company), a settlement, and a clearing account with two inflows and one allocation; assert balances, ages and the oldest id equal on both engines.
6. **Port, snapshot, tests.** Session `listCounterpartyBalances()`, port and `PhoneLedgerSnapshot.counterpartyBalances` + `directionTotals`; `unsettledClearing` rows gain the two fields and C2's banner (`today-screen.tsx`) names the transaction's payee/date when present (S04's banner text already has a slot for it — check `shell.unsettled*` keys). Controller test: a fixture with the §6.6 table's four events yields `+200`, `0`, `−200`, `0` in turn.
7. **Report.** Commit, push `feature/e1-debt-figures`; report PR *"Who owes what, and what is unallocated — on the phone"*, quoting both cards' *Done when* and naming the §8 reading written into the spec.
