# Wave 4 · what every plan in this wave shares

> Read this first; every wave-4 plan points here instead of repeating it.

**Base:** `main` at or after PR #101 (wave 3 all landed: C2–C6 screens, D3 capture components, D4a category sheet, DESK1 band). `main` holds: every class-F figure in `money.ts` with its SQL twin and differential test (A1); every transaction, account, group and category operation as a local executor (A2, A3); the replica and outbox (A4); `Dock`, `Keypad`, `DateField`, `SearchField` (D3); `CategorySheet` with D2's proposal (D4a); S04, S16, S10, S09, S19 on the phone (C2–C6).

**Rules:** `CLAUDE.md`, the arc design §4, and `2026-09-04-wave-3-shared.md`'s three rules (the gate protocol, Reanimated only, one screen file composed from `packages/ui` through `useLedgerController()`), plus two this wave adds:

1. **The orchestrator runs the gate.** An agent stops at *every test passes under `pnpm vitest run`* and Biome clean (`pnpm biome check .`), commits with a message file, pushes the branch, and reports. It does **not** run `pnpm verify`, does not open the PR, and does not touch `/tmp/waltning-verify.lock`. Wave 3 showed the full gate (typecheck + vitest + Playwright) stalls an agent more often than it passes; the orchestrator rebases, gates, updates visual baselines and opens the PR. If a commit is refused by the hook, the agent commits with `--no-verify` **only for that WIP commit** and says so in its report — the orchestrator's final gate is what lands.
2. **An executor is the operation's whole contract on the phone.** Input in `packages/core/src/registry/inputs.ts` (own delimited block), one `defineLocalExecutor` file per operation under `packages/ledger/src/<domain>/`, registered in `registry.ts` inside a delimited block, a session method (`write(executor, input, capture)`), a port method, a controller method returning `{ id } | { fieldErrors }`, and a test that breaks every refusal once. Where the spec names a guarantee, mirror it as a SQLite `CHECK` or partial index in `packages/schema/src/*.sqlite.ts` and regenerate `ddl.ts` (`pnpm ledger:generate`); a guarantee only in code is not a guarantee.

**Shared vocabulary that exists — compose, do not reinvent:** everything wave 3 listed, plus `SearchField`, `DateField`, `Keypad`, `Dock` (`transactions/`), `CategorySheet` (`categories/`), `DeskBand`, `useBreakpoint` (`shell/`), `TransferAmount`, `AmountField`, `FxAmount`, `Amount` (`fx/`), `MatchWarning` (`states/`), `createDevicePreference` / `useDevicePreference` (`packages/client/src/device/`), `readPayeeHistory` + `proposeCategory` (D2), `parseCapture` (D1, desk only).

**What no wave-4 PR builds** (named so nobody invents it): voice, receipts, the conversational mode and `TrailRow` (excluded from arc 1); duplicate-at-save (`computations.md` §9 — the board's *duplicate detection is under-designed for local-first* gap stands); `sync_fx_rates` · `force_sync` · `backfill_fx_rates` (they fetch from a central bank; the adapters are `packages/db/src/fx/`, server-side, and arc 2's sync brings them to the phone) and therefore `FxStatusChip` and `SyncLog`'s event half; debt reassignment (`debt_reassignments` is a server-only migration table — `0004`'s own comment — fed by the Money Manager import, `#e8`); J08's allocation screen (`design/gaps` G2 — its write model is undecided, see below); the agent.

**A decision this wave needs from the owner, not an agent — J08's allocation writes.** J08 says the group bill is *one* Quick add row *from* the clearing account and each share is a `debt`-role row, and `computations.md` §8 says allocations *consume clearing inflows*. Those only agree if the bill enters clearing as an inflow (a transfer bank → clearing) and each share leaves it (an expense from clearing carrying the counterparty, `debt`). The specs do not say that in one place. E1 builds §8's `find_unsettled` on the reading that **inflows to clearing are consumed FIFO by outflows from it** and states so in `computations.md` §8; the allocation *screen* waits for the decision.

**Order inside the wave.** 4a runs first, in parallel, off `main`: **D4b** (S05 on the Dock), **E1** (§7/§8 figures and readers), **E2** (counterparty and settlement operations), **E3** (§4/§4a figures, rates on the replica, the FX operations). 4b runs once its inputs merge: **D5** (after D4b), **E4** (S15, S12, S13 — after E1, E2, E3), **E5** (S14, S31 — after E2, E3, D4b), **E6** (S17, S18 — after E3). 4c: **J07 + J16 acceptance** (after E4, E5), written then.
