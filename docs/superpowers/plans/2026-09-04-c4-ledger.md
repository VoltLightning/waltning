# C4 · S10 Transactions list — Implementation Plan (wave 3b)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Read `2026-09-04-wave-3-shared.md` first. Needs D3 (`SearchField`) and D4a (category sheet) merged.

**Goal:** The Ledger tab is the whole ledger: searchable, filterable by account, category, scope and date range, grouped by day with a running total, and a row can be recategorised with a swipe.

**Architecture:** One replica read, `packages/ledger/src/transactions/search-transactions.ts`: `searchTransactions(db, filter, page) → { rows, nextCursor, total: { count, sum per currency, capitalSum per currency } }` — filter `{ text?, accountIds?, categoryIds?, scope?: "all"|"mine"|"shared"|"business", from?, to? }`, text matched against folded payee and note and the amount's digits (D1's `fold`; SQLite `LIKE` on a stored folded column is not there — fold in SQL with `lower()` and accept diacritics-sensitive matching **only if** the row count makes a JS filter unreasonable; prefer reading candidates and folding in JS at arc-1 sizes, and say which). Cursor = `(date, id)` keyset, 50 per page. Live rows only. Totals per currency, never summed across. Exposed as `controller.searchTransactions(filter, cursor)` returning a page (not part of the snapshot — a filtered list is a query, not the ledger's state). Screen `apps/mobile/src/ledger-screen.tsx` replaces the stub: `SearchField`, a `Chip` row of active filters (each with ✕; `+ Filter` opens `FilterSheet` over `BottomSheet` with account `MultiSelect`, category (D4a's sheet, multi-pick mode if it has one, else a `MultiSelect` of leaves), scope `SegmentControl`, two `DateField`s), the running-total line, then a `FlatList` (react-native — no virtualised-table library) of day sections with `TransactionRow`, a `TransferRow` for transfers (new, `transactions/transfer-row.tsx`, one row showing both accounts), and swipe on a row via gesture-handler's `Swipeable`-equivalent built on `Gesture.Pan` (short swipe reveals *Categorise* → category sheet → `categorize_batch` with one id; long swipe → S09 when C5 lands, else the same). Route param `?account=<id>` (from C2's banner) arrives as a **visible** chip, never a silent filter (S10 §7 shared).
