# D4b · S05 Quick add on the Dock — Implementation Plan (wave 4a)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Read `2026-09-04-wave-4-shared.md` first.

**Goal:** Quick add is the screen S05 §3 draws: the amount as the largest thing on the screen, the chip row as the whole model, and the dock — mode row, keypad, full-width Save — fixed to the bottom in thumb reach. A known account and category go from `+` to Save in a dozen taps.

**Architecture:** `apps/mobile/src/quick-add-screen.tsx` stops rendering `QuickAddForm` inside a `Card` and composes `QuickAddComposer` (`packages/ui/src/transactions/quick-add-composer.tsx`, new) above `Dock` with `Keypad` in its slot. `QuickAddForm` stays for the web build below the breakpoint and for DESK2's fallback — it is not deleted; the phone route simply stops using it. `AmountField` gains a **read-only display mode** (`variant="hero"`, no `TextInput`, value driven by `Keypad`); `parseAmount` is unchanged. Keypad taps edit a *raw string* held by the screen (`"48,90"`), and `parseAmount(raw)` is what reaches the draft — one decimal path, no second parser. The last-used account is a device preference (`waltning.lastCapture`, `{ accountId, at }`) through `createDevicePreference`, honoured for **four hours** (S05 §9.2 left the window unset; this PR sets it and says so in the spec).

**Spec:** `screens/S05-quick-add.md` §3 mobile, §4, §6, §7, §8, §9 · `flows/J02-daily-capture.md` §3, §6 · `design-system/05` §5.1 (`Dock`) · `03` §3.7 · `computations.md` §14 (proposal marker) · `SPEC.md` §6.6 (role never defaulted), §7.0a (date).

**Board card closed:** *S05 · Quick add* (the keypad mode; voice, photo, converse stay excluded and the card's write-up says so).

**Branch:** `feature/d4b-quick-add-dock` off `main`.

## Spec changes this PR makes (same PR, never silently)

- S05 §3 mobile: the chip row gains **payee** — `[+ payee]`, typed, optional — between category and date. The keypad path had no payee, so D2's memory could never fire on it and every keypad row reached the ledger nameless. J02 §3's chip list says the same.
- S05 §9.2: *"Window length is unset"* → **four hours**, named as `LAST_USED_WINDOW_MS` in `packages/client/src/transactions/last-capture.ts`.
- S05 §3's "disposable preview profile" paragraph is deleted; the screen is now the drawn one.

## Tasks

1. **`AmountField` hero mode.** `variant?: "field" | "hero"`; `hero` renders `display-hero` tabular numerals with the currency affix (or none — the existing *not yet known* rule), no `TextInput`, `accessibilityRole="text"` with the amount as label; takes `value: string` (the raw typed string, shown with the locale's decimal mark via `decimalMark`) and no `onChange`. Story `Hero`, `HeroEmpty`, `HeroNoCurrency`. Test: `"48,90"` renders as `48.90` in English and `48,90` in Polish, affix follows the account currency.
2. **Keypad → raw string.** `packages/ui/src/transactions/amount-keys.ts`: `applyKey(raw, key): string` — digits append (leading `0` rule: `"0"` + `"5"` → `"5"`; `"0"` + `","` → `"0,"`), one comma only (a second is ignored), `delete` drops the last char, at most **two** fraction digits for a 2-decimal currency (`decimals` parameter — GEL/PLN/USD all 2 here; pass the account's), an empty result is `""`. Pure, tested, no React.
3. **`QuickAddComposer`.** `packages/ui/src/transactions/quick-add-composer.tsx`. Header row: `✕` (`IconButton`, `common.cancel`) left, the type `Select`-look (`expense ▾` / `income ▾`) right, out of the thumb zone per §9.1. Hero `AmountField`. Chip row, wrapping, every chip ≥44px (`touchTarget.min`): account (`Cash · PLN` / placeholder `transactions.account`), category (name / placeholder; **proposal state** when D2 proposes: filled with the `machine` variant `Chip` already has and the §14 marker below 0.85), payee (`+ payee` / the text), date (`Today` / the date — opens D3's `DateField` in a `BottomSheet`), scope (`Mine` · `Shared` · `Business` — `Shared` is read-only when the account is shared; tapping toggles `isBusiness` on an own account; S05 §4's `SegmentControl` lives inside the sheet the chip opens), note (`+ note` / first 24 chars), counterparty (`+ person`, offered only when the ledger holds any; picking one opens the **role** picker in the same sheet, never defaulted — §6.6). Props are controlled: the screen owns the draft; the composer renders and emits. `fieldErrors` render under the chip they name (`FieldErrorMap`, same keys as `QuickAddForm`).
4. **The Dock.** Compose `Dock` with `modes` = keypad enabled, `◉` `▣` `💬` disabled (D3 already labels them *later*), `Keypad` in the slot, Save full-width, `saveDisabled` until `parseAmount(raw)` is non-null **and** an account is chosen (§9.2: an empty account chip disables Save). Save shows the pressed state with width held.
5. **Last-used account.** `packages/client/src/transactions/last-capture.ts`: `createLastCapturePreference(store)` over `createDevicePreference` with codec `{ accountId, at }`; `useLastUsedAccount(pref, now, accounts)` returns the id when `now − at < LAST_USED_WINDOW_MS` and the account is still capturable, else `null`. The screen writes it on every successful save. The chip in that state is **machine-filled** (`Chip variant="machine"`, S05 §3's third state) so it reads as a guess, and its sheet shows *from your last capture, 14:20*. Tests: inside the window fills, outside does not, an archived account does not.
6. **Proposal.** When payee is non-empty and its fold differs from the last one proposed, the screen runs `proposeCategory(payee, readPayeeHistory)` — expose `listPayeeHistory()` on the session/port/snapshot (D2 built the reader; nothing calls it) — and passes the result both to the category chip and to `CategorySheet.proposal`. A proposal is applied to the draft only when the person taps the chip's *Use* or picks in the sheet; the chip shows it, the draft does not hold it (P2: machine-filled declares itself, and nothing is written until Save).
7. **The screen.** `quick-add-screen.tsx` rewritten: draft state (`raw`, `type`, `accountId`, `categoryId`, `payee`, `date`, `note`, `isBusiness`, `counterpartyId`, `counterpartyRole`) → `QuickAddDraft` (add `payee: string` to the draft type and to the controller's `createTransaction` mapping — `payee` already exists on `createTransactionInput`). `✕` discards with a confirm only when the account chip is machine-filled (the one machine-filled thing on the keypad path); otherwise straight back. Haptic on Save through `apps/mobile/src/platform.ts` (`expo-haptics` is bundled; the web build's `platform.ts` no-ops it). `router.dismissTo("/")` on success, as today.
8. **Stories and tests.** Stories on the composer: `Empty`, `AmountOnly`, `ReadyToSave`, `WithProposal`, `LowConfidence`, `LastUsedAccount`, `WithCounterparty`, `FieldErrors`, both themes. Screen test under react-native-web: tap `4` `8` `,` `9` `0`, pick an account, Save → the controller received `{ amount: "48.90", … }`; Save disabled with no account; a refusal lands under its chip. Keys in `en.ts` **and** `pl.ts`.
