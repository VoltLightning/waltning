# E3 · §4 and §4a, rates on the replica, and the FX operations — Implementation Plan (wave 4a)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Read `2026-09-04-wave-4-shared.md` first.

**Goal:** A figure in one currency can be shown in another without the rate being applied upside down (§4); a cross-currency transfer's cost is a number (§4a); a rate can be read for any pair and date the replica holds, with carry-forward capped at ten days; and the seven FX operations that change local state exist as executors, so a currency can be added, pinned, archived, re-sourced, and a rate set or cleared by hand — offline, audited through the outbox.

**Architecture:** `money.ts` gains `convert`, `toPivot`/`fromPivot` by `UnitsPerPivot` (the `fx_rates` direction), `margin`. `packages/ledger/src/currencies/read-rate.ts`: `readRate(db, { base, quote, date })` → `{ rate: UnitsPerPivot; source; asOf; carriedDays } | undefined` — the latest row `≤ date`, refused past ten days (§7.7) — and `readCoverage(db)` per currency (first/last date, row count, share of days since first). The **display currency** is a device preference (`waltning.displayCurrency`, `createDevicePreference`), never a write (§7.0). Executors under `packages/ledger/src/currencies/`: `add_currency` `archive_currency` `set_rate_source` `set_pinned` `change_pivot` `set_manual_rate` `clear_manual_rate`. Not built: `sync_fx_rates` `force_sync` `backfill_fx_rates` — they fetch, and arc 2's sync carries them (shared plan).

**Spec:** `computations.md` §4, §4a · `SPEC.md` §7.0, §7.5, §7.6, §7.7 · `operations.md` FX rows · `screens/S17` §5, §6 · `S18` §5, §8 · `architecture/14` §14.6 (capture needs a rate) · `design-system/04` §4.1–4.3, 4.5.

**Board cards closed:** *§4 display conversion · class R* · *§4a FX margin · class S* · *Writes — FX (8 ops)* (seven on the phone; the three sync ops named as arc 2) · *Lift the preview's USD-only currency boundary* · the FX half of *Reads — debt and FX (6 ops)*: `get_currencies` (exists — `readCurrencies`), `get_fx_rates`, `get_fx_coverage`.

**Branch:** `feature/e3-fx` off `main`.

## Tasks

1. **§4 in `money.ts`.** `toPivotByDivision` exists; add `fromPivot(p, rate: UnitsPerPivot) = p × rate` and `convert(x, rateFrom: UnitsPerPivot, rateTo: UnitsPerPivot) = fromPivot(toPivotByDivision(x, rateFrom), rateTo)`, full precision, caller rounds. Property test: `convert(convert(x, a, b), b, a)` equals `x` to eight places; `convert(x, r, r)` is `x`. The §4 worked figure: `565.20 PLN` at `3.8100` → `148.35 USD` (rounded at the boundary).
2. **§4a.** `margin({ amountOriginal, fxRate, toAmount, toFxRate }) → { marginPivot, marginPct, realizedRate }` — `realizedRate = toAmount ÷ amountOriginal`, never stored. The §7.5 worked example: `150.00 USD` → `565.20 PLN`, reference `3.8100` → margin `1.65 USD`, `1.10 %`. A negative margin is returned, never clamped (test it). Server twin as a SQL expression in `packages/db/src/figures/margin.ts` over `transactions_valued`; differential test row added.
3. **`readRate` and `readCoverage`.** As described; `carriedDays` is `date − asOf`; `undefined` past ten days. `readCoverage`: per non-archived currency `{ code; source; firstDate; lastDate; days; coveragePct }` — `coveragePct` is rows ÷ calendar days from `firstDate` to today, an integer 0–100, so *0.5 %* is a number a screen can show (S17 §8). Tests: exact day, carry-forward within cap, past cap, no rows.
4. **Inputs and executors.** `/* ── FX ── */`: `addCurrencyInput { code (ISO, 3 upper), name, symbol, symbolPosition: P|S, decimals 0..8, rateSource: FX_SOURCE | null, pinned }` — refuses an existing code (archived → un-archive instead, say so); `archiveCurrencyInput { code, version }` — refuses the pivot and any currency an account or live transaction references (S17 §6 *Gated*), mirrored by a SQLite trigger? No: SQLite has no cross-table trigger in the replica's DDL — a refusal in the executor and a comment naming the server-side trigger; `setRateSourceInput { code, version, rateSource }`; `setPinnedInput { code, version, pinned }`; `changePivotInput { code }` — **refused while any transaction exists** (*change the pivot before the first capture — S29a's first-run step*; there is no re-rating on a phone alone), else flips `isPivot` and rewrites every `fx_rates` row by division so the table stays quoted against the pivot; `setManualRateInput { base, quote, from, to, rate: zUnitsPerPivot }` — writes one `manual` row per day across the range, refuses to overwrite an existing `manual` row unless `overwriteManual: true` (S18 §8's second confirmation is the screen's; the input carries the answer), returns `{ written, replacedManual }`; `clearManualRateInput { base, quote, from, to }` — deletes `manual` rows only. Every rate input refuses `base !== pivot`.
5. **Capture in any capturable currency.** `readCurrencies.capturable` already answers from `fx_rates`; after `set_manual_rate` for a pair, a capture in that currency succeeds offline and produces `amount_pivot = amount × (1 ÷ rate)` — write that end-to-end test (the card's *Done when*), and the refusal when the rate is absent, in `executors.test.ts`.
6. **Display currency.** `packages/client/src/currencies/display-currency.ts`: `createDisplayCurrencyPreference(store, pivot)` (default: the first pinned currency, else the pivot) + `useDisplayCurrency`. `useFxAmount(api)`-style hook **not** built here — `FxAmount` takes a rate prop; E4/E5 screens call `readRate` through the port (`readRate(pair, date)` on session/port) and pass it. Session/port: `readRate`, `readCoverage`, `listFxRates({ base, quote, from, to })` (S18's table, paged by date), plus the seven writes → controller `{ id | code } | { fieldErrors }`.
7. **Report.** Commit, push `feature/e3-fx`; report PR *"Rates the phone holds, and the figures that use them"*, quoting the cards, naming the sync ops as arc 2, and the `change_pivot` refusal.
